# Claude 실행 지침 (Virtual Football Manager)

1. 프로젝트를 새로 쓰지 않는다. 기존 엔진·데이터·저장 구조를 재사용한다.
2. 정상 동작하는 기능을 임의로 삭제하지 않는다. 숨기거나 옮길 때는 이유를 남긴다.
3. 실제 리그·구단·선수의 이름, 엠블럼, 유니폼, 사진을 사용하지 않는다. 모든 데이터는 가상이다.
4. 세이브는 세이브마다 독립된 월드 사본을 가진다. 전역 월드를 여러 모드가 함께 바꾸는 구조를 만들지 않는다.
5. 기존 세이브를 자동으로 변경·삭제하지 않는다. 세이브 스키마 v4 이하는 구버전 원본으로 보호한다.
6. 새 데이터 필드는 선택(optional)으로 추가하고, 세이브 스키마 버전과 Dexie DB 버전을 구분한다. Dexie 버전은 테이블·인덱스가 실제로 바뀔 때만 올린다.
7. 경기 엔진 호환을 위해 능력치 25개·포지션 12종을 유지한다.
8. 작게 나눠 수정하고, 단계마다 `npm test`, `npx tsc -b`, `npm run build`를 실행한다. 실패하면 원인을 해결한 뒤 다음 단계로 간다.
9. 실행하지 않은 테스트, 구현하지 않은 기능을 완료로 보고하지 않는다.
10. 보고는 한국어로 짧게: 한 일, 바뀐 파일, 테스트 결과, 남은 위험.
