# K-LEAGUE MANAGER — 최종 게임 개발 기획서
버전: 1.0  
기준일: 2026-11-03  
프로젝트 유형: 싱글 플레이 웹 기반 축구 구단 경영 시뮬레이션

---

## 0. 프로젝트 개요

**K-LEAGUE MANAGER**는 실제 K리그 구단과 선수 데이터를 기반으로 사용자가 감독이 되어 구단을 운영하는 장기 커리어형 축구 경영 게임이다. 사용자는 구단을 선택하고 선수단·전술·훈련·이적·재정을 관리하며, 날짜를 진행해 리그 일정을 소화한다. 경기에서는 라인업, 교체, 전술 변경을 직접 지시하고 경기 시뮬레이션 결과를 확인한다.

### 확정된 사용자 요구사항

| 항목 | 확정 사양 |
|---|---|
| 선수 및 구단 | 실제 K리그 구단·선수 중심 |
| 선수 카드 | 실제 선수 사진 기반 |
| 시간 진행 | 게임 내 날짜가 흐르는 실시간형 진행(일시정지/속도 조절) |
| 경기 | 경기 중 직접 전술·교체 개입 |
| 플랫폼 | PC 우선 웹, 태블릿·모바일 반응형 |
| 플레이 | 싱글 플레이 |
| 시각 디자인 | 첨부 레퍼런스의 네이비·골드 선수 커리어 카드 |
| 핵심 재미 | 구단 운영, 선수 성장, 이적, 전술, 경기, 다년 커리어 |

여기서 '실시간 날짜 진행'은 현실의 실제 시각과 동기화하는 온라인 게임이 아니라, **게임 내 시계를 사용자가 진행·정지·속도 조절하는 방식**을 뜻한다. 브라우저를 닫아도 게임 시간이 임의로 흘러가지 않는 것을 기본값으로 한다.

## 1. 제품 목표와 핵심 원칙

### 1.1 핵심 플레이 루프

1. 구단 선택 및 감독 생성
2. 현재 선수단과 재정·구단 목표 파악
3. 전술과 주전 라인업 설정
4. 훈련·휴식·스카우트·계약 업무 수행
5. 게임 날짜 진행
6. 경기 전 준비 및 경기 직접 지휘
7. 경기 결과·선수 기록·순위 반영
8. 이적시장 및 선수단 개선
9. 시즌 종료·승격/강등·시상
10. 다음 시즌 진행 및 장기 커리어 축적

### 1.2 설계 원칙

- 모든 화면의 데이터는 동일한 게임 상태(Game State)를 참조한다.
- 경기 결과는 선수 능력치, 포지션 적합도, 전술, 컨디션, 체력, 사기, 홈 이점, 경기 상황을 반영한다.
- 모든 주요 버튼은 실제 동작해야 한다. 미구현 기능을 작동하는 것처럼 표시하지 않는다.
- 선수·구단 데이터의 출처, 기준일, 수정 이력을 기록한다.
- 실제 선수의 이름·사진·엠블럼·상표 사용 권한을 확인하지 않은 상태에서 공식 라이선스가 있다고 표현하지 않는다.
- 외부 데이터 공급이 중단되어도 저장된 게임은 계속 플레이할 수 있어야 한다.
- 게임 밸런스와 시뮬레이션은 재현 가능한 난수 시드로 디버깅할 수 있게 한다.

## 2. 범위 및 현실적인 1차 출시 기준

### 2.1 MVP(최초 플레이 가능 버전)

MVP는 아래 항목이 하나의 완결된 플레이 루프로 연결되는 상태다.

- K리그 구단 선택
- 구단별 선수단 및 선수 상세 카드
- 감독 생성 및 새 게임
- 게임 날짜 진행·일시정지·속도 조절
- 경기 일정과 리그 순위표
- 포메이션·선발·벤치 구성
- 기본 전술 설정
- 텍스트/2D 이벤트 기반 경기 진행
- 경기 중 교체 및 전술 변경
- 경기 결과와 득점·도움·평점 반영
- 선수 컨디션·체력·부상 기본 처리
- 자동 저장·수동 저장·불러오기

### 2.2 MVP 이후 확장

- 이적 협상과 임대
- 계약·연봉·보너스
- 훈련 및 개인 성장
- 유소년 아카데미
- 스카우트와 선수 잠재력
- 코치진·시설
- 구단 재정 고도화
- 컵대회 및 아시아 대회
- 감독 평판·구단 목표·경질
- 뉴스·팬 반응·라이벌 이벤트
- 고급 경기 엔진 및 시각화

### 2.3 초기 버전에서 하지 않을 일

- 온라인 멀티플레이
- 실시간 사용자 간 이적시장
- 실제 경기 중계 데이터와의 동기화
- 무단 크롤링으로 확보한 선수 사진·유료 데이터의 배포
- 초기부터 완전한 3D 경기 엔진 제작
- 모바일 앱 패키징

## 3. K리그 데이터 및 라이선스 전략

### 3.1 데이터 구조

실제 K리그 구단과 선수 데이터를 기반으로 하되, 데이터 공급 방식은 교체 가능한 어댑터 구조로 만든다.

필수 데이터:
- 리그 및 시즌
- 구단 ID, 구단명, 연고지, 홈구장
- 선수 ID, 이름, 생년월일 또는 나이, 국적, 신장, 체중
- 포지션, 등번호, 소속 구단
- 출전·득점·도움 등 확인 가능한 기록
- 데이터 출처 URL 또는 출처 식별자
- 수집/수정 기준일
- 데이터 사용 권한 상태

능력치(예: 패스 1~100, 결정력 1~100)는 공식 공개 데이터가 아닐 수 있다. 출처가 없는 능력치는 **게임용 추정치**로 표시하고 실제 공식 평가처럼 표현하지 않는다. 선수 잠재력(POT), 성격, 숨겨진 능력치도 게임 밸런스용 창작 데이터로 분리한다.

### 3.2 데이터 공급 우선순위

1. 정식 라이선스가 있는 데이터/API
2. 데이터 이용 약관이 명확한 공식 공개 자료
3. 사용자가 직접 입력하거나 합법적으로 보유한 CSV/JSON
4. 개발 테스트용 가상 데이터

공식 API 접근 권한·요금·호출 제한·재배포 허용 여부를 확인하기 전에는 API가 무료이거나 상업적 재사용이 가능하다고 가정하지 않는다. 웹페이지 자동 수집은 각 사이트의 이용약관과 robots 정책, 저작권을 확인한 뒤 허용되는 범위에서만 고려한다.

### 3.3 사진 및 엠블럼 처리

- 실제 선수 사진은 사용·저장·재배포 권한이 확인된 파일 또는 공급처만 사용한다.
- 사진 URL을 무단으로 핫링크하지 않는다.
- 권한이 없거나 사진이 누락되면 포지션별 기본 실루엣/일러스트를 표시한다.
- 사진 파일에는 출처, 라이선스, 권리자, 사용 범위, 확인일을 기록한다.
- 사용자가 로컬에서 개인용으로 사진을 넣을 수 있는 기능과, 배포용 빌드에서 권리 확인된 에셋만 포함하는 정책을 분리한다.
- 구단 엠블럼도 동일하게 권리 상태를 관리한다.

### 3.4 데이터 임포트

MVP부터 관리자/개발자용 CSV·JSON 가져오기 기능을 준비한다.
- 필수 필드 누락 검사
- 선수 ID 중복 검사
- 구단 ID 연결 검사
- 포지션 표준화
- 숫자 범위 검사
- 가져오기 전 미리보기
- 오류 행 다운로드 또는 화면 표시
- 원본 파일명과 가져온 날짜 기록

데이터 갱신이 게임 중인 세이브의 선수 기록을 덮어쓰지 않도록 한다. 새 데이터베이스 버전과 기존 세이브의 선수 스냅샷을 분리한다.

## 4. 게임 세계 및 시간 시스템

### 4.1 게임 시간

- 기본 단위: 하루
- 기본 속도: 일시정지 / 하루씩 / 빠르게 / 매우 빠르게
- 사용자가 언제든 정지할 수 있다.
- 경기, 이적 제안, 부상, 계약 만료, 중요 뉴스 발생 시 자동 정지 옵션 제공
- 브라우저 탭이 비활성화되었을 때 과도한 타이머 누적을 방지한다.
- 게임 내 날짜와 실제 기기 날짜를 별도 관리한다.

### 4.2 날짜 이벤트 처리 순서

하루가 진행될 때 서버가 없는 로컬 MVP 기준으로 다음 순서를 고정한다.

1. 날짜 증가
2. 계약 만료·임대 기간 확인
3. 부상 회복 및 컨디션 회복
4. 훈련 및 선수 성장 처리
5. 스카우트·협상·이적 이벤트 처리
6. 일정에 등록된 경기 확인
7. 뉴스·알림 생성
8. 자동 저장

동일 날짜 이벤트가 중복 실행되지 않도록 `processedEventIds` 또는 날짜별 처리 기록을 둔다.

### 4.3 시즌 및 대회

K리그의 실제 운영 방식은 시즌별로 변경될 수 있으므로 일정·라운드·승강 규칙을 코드에 고정하지 않는다. `CompetitionFormat` 설정 데이터로 관리한다.

필수 모델:
- Competition
- Season
- Stage
- Round
- Fixture
- PromotionRelegationRule

초기에는 사용자가 선택한 시즌의 경기 수, 라운드, 순위 결정 규칙을 데이터 설정으로 입력한다. 공식 일정 데이터를 확보하지 못하면 테스트용 일정임을 명시한다. 승점 기본값은 승리 3, 무승부 1, 패배 0이며, 동률 시 골득실·다득점 등 순위 규칙은 시즌 설정에 따른다.

## 5. 구단 선택 및 감독 커리어

### 5.1 새 게임 흐름

1. 타이틀 화면
2. 새 게임
3. 감독 프로필 설정
4. 리그/구단 선택
5. 구단 소개 및 시즌 목표
6. 초기 선수단·재정 확인
7. 첫날 대시보드 진입

### 5.2 감독 프로필

- 감독 ID
- 이름
- 국적
- 나이(선택)
- 전술 성향
- 선수 육성 성향
- 초기 평판
- 커리어 시작일
- 소속 구단 이력
- 통산 경기·승·무·패·우승 기록

MVP에서는 감독 능력치를 단순화하고, 이후 전술·동기부여·훈련·유소년 육성 능력으로 확장한다.

## 6. 선수 데이터 및 능력치

### 6.1 기본 정보

- 고유 선수 ID
- 표시 이름
- 영문 이름(선택)
- 국적
- 생년월일/나이
- 신장·체중(자료가 있을 때만)
- 주 포지션 및 보조 포지션
- 주발
- 등번호
- 소속 구단
- 계약 시작일·종료일
- 사진 에셋 ID
- 데이터 출처 및 기준일

### 6.2 능력치

능력치는 1~100 정수로 관리한다. MVP에서는 포지션에 필요한 최소 세부 능력치만 사용하고, 화면에서 공격·패스·수비·피지컬·정신 그룹으로 보여준다.

- 공격: 결정력, 슈팅, 위치 선정, 헤딩
- 패스: 짧은 패스, 긴 패스, 시야, 크로스
- 수비: 태클, 대인 방어, 위치 선정, 인터셉트
- 피지컬: 속도, 가속, 체력, 몸싸움, 점프
- 정신: 판단력, 침착성, 리더십, 적극성, 팀워크

### 6.3 OVR 및 POT

- OVR은 포지션별 가중 평균으로 계산한다.
- 같은 선수라도 포지션이 다르면 해당 포지션 OVR이 달라질 수 있다.
- POT는 성장 가능성을 표현하는 게임 시스템 값이다.
- OVR/POT 계산식은 별도 모듈에 두고 밸런스 테스트가 가능하도록 한다.
- 선수의 게임용 추정 능력치를 공식 K리그 기록처럼 표기하지 않는다.

### 6.4 선수 상태

- 체력(0~100)
- 컨디션(0~100)
- 사기(0~100)
- 경기 감각(0~100)
- 부상 상태 및 예상 복귀일
- 출전 역할
- 출전 시간 누적
- 팀 내 만족도

### 6.5 선수 프로필 카드

첨부 이미지의 정보 위계와 분위기를 참고하되 독자적인 UI로 제작한다.

상단:
- 이름, 국적, 주 포지션, 등번호
- PEAK OVR 또는 최고 OVR
- 현재 OVR

중앙:
- 실제 사진(권리 확인된 에셋)
- 사진 미보유 시 기본 실루엣
- 나이, 신장, 주발, 소속 구단

기록:
- 통산 출전
- 통산 득점
- 통산 도움
- 평균 평점
- 우승 및 개인상
- 시즌별 소속 구단과 출전 기록

주의: 통산 기록은 게임 세이브 안에서 생성된 기록과 외부에서 가져온 실제 기록을 구분한다. 두 기록을 합산할 때 중복 집계를 방지한다.

## 7. 선수단 및 라인업

- 전체 선수 목록 및 포지션 필터
- 이름·나이·OVR·POT·주급·계약 만료 정렬
- 부상·경고 누적·출전 정지 상태 표시
- 선발 11명 및 벤치 구성
- 포지션 적합도 표시
- 선발 불균형 및 등록 규정 경고
- 주장·부주장 지정
- 선수별 출전 시간 및 최근 폼

MVP에서는 드래그 앤 드롭과 선택형 배치를 모두 고려하되, 키보드·마우스만으로도 조작할 수 있어야 한다.

## 8. 전술 시스템

### 8.1 기본 포메이션

4-4-2, 4-3-3, 4-2-3-1, 3-4-3, 3-5-2, 4-1-4-1을 기본 제공한다. 포메이션은 좌표 기반으로 표현하고 사용자가 선수 위치를 조정할 수 있도록 확장한다.

### 8.2 팀 전술

- 공격 성향: 수비적 / 균형 / 공격적
- 압박 강도: 낮음 / 보통 / 높음
- 수비 라인: 낮음 / 보통 / 높음
- 전개 속도: 느림 / 보통 / 빠름
- 패스: 짧게 / 혼합 / 직접
- 공격 방향: 중앙 / 측면 / 혼합
- 역습: 사용 / 미사용
- 수비 전환: 즉시 압박 / 재정비

전술은 경기 엔진 입력값으로 연결되어야 하며 단순한 장식 설정이 아니어야 한다.

## 9. 경기 엔진 및 직접 경기 운영

### 9.1 경기 엔진 원칙

경기 결과를 단일 난수로 정하지 않는다. 양 팀의 선수 능력, 라인업, 포지션 적합도, 전술 상성, 체력, 컨디션, 사기, 홈 이점 등을 기반으로 경기 이벤트를 생성한다.

MVP는 텍스트 기반 라이브 중계와 경기 타임라인으로 시작한다. 이후 2D 탑다운 경기장 애니메이션을 추가할 수 있도록 이벤트 모델을 분리한다.

### 9.2 경기 흐름

- 경기 전: 선발·벤치·전술·선수 컨디션 확인
- 전반 시작
- 1분 단위 또는 이벤트 단위 진행
- 득점·슈팅·파울·경고·부상 이벤트
- 하프타임: 전술 및 선수 교체
- 후반 진행
- 추가 시간
- 경기 종료
- 통계 및 선수 평점 산출

### 9.3 경기 중 사용자 조작

- 일시정지 / 재개
- 진행 속도 조절
- 선수 교체
- 포메이션 변경
- 공격/수비 성향 변경
- 압박·수비 라인·패스 설정 변경
- 경기 이벤트 로그 확인

교체 가능 횟수 및 교체 창 등 규칙은 시즌별 대회 설정으로 관리한다.

### 9.4 경기 결과

- 스코어
- 득점자·도움
- 슈팅·유효 슈팅
- 점유율
- 패스 성공률
- 파울·경고·퇴장
- 선수별 출전 시간·평점
- MOM
- 부상 및 징계

경기 종료 시 선수 시즌 기록, 통산 기록, 구단 기록, 리그 순위, 득점·도움 순위가 한 번만 업데이트되어야 한다.

### 9.5 공정성 및 재현성

경기 시작 시 난수 시드를 생성하고 저장한다. 같은 세이브와 같은 입력 조건에서 디버그 재현이 가능해야 한다. 결과가 지나치게 전술 하나에 치우치지 않도록 시뮬레이션 테스트를 수행한다.

## 10. 일정·순위·대회

- 월간 캘린더

- 경기 일정 목록
- 홈/원정 구분
- 리그 순위표
- 승·무·패·득실·승점
- 팀 득점·실점
- 득점·도움 순위

경기 일정과 순위 규칙은 대회 설정에 따라 생성·계산한다. 시즌별 규칙 변경에 대비해 로직과 데이터를 분리한다.

## 11. 이적시장 및 계약 (PHASE 2)

- 선수 검색 및 필터
- 이적료 제안
- 구단 간 협상
- 선수 계약 협상
- 자유계약
- 임대 영입 및 임대
- 판매·방출
- 계약 만료 알림
- 이적 예산과 주급 예산

AI 구단의 영입 판단은 포지션 공백, 예산, 선수 나이, 능력, 잠재력, 계약 기간을 고려한다. 초기에는 간단한 규칙 기반 AI로 구현한다.

## 12. 훈련·성장·부상 (PHASE 2~3)

훈련 유형:
- 공격, 수비, 패스, 피지컬, 개인 포지션 훈련, 휴식

성장 요인:
- 나이, POT, 훈련 강도, 출전 시간, 코치 능력, 부상 이력

훈련 강도가 높을수록 피로와 부상 위험도 함께 증가하도록 한다. 선수 성장은 급격하지 않게 하고 시즌 단위로 검증한다. 선수 노화와 은퇴도 장기 커리어에서 처리한다.

## 13. 구단 재정 (PHASE 2)

수입:
- 중계권, 입장 수입, 스폰서, 선수 판매, 대회 상금

지출:
- 선수·코치 급여, 이적료, 운영비, 시설 및 훈련비

재정 화면은 현재 잔액, 이적 예산, 주급 예산, 월별 손익, 향후 계약 부담을 보여준다. 재정 파산 및 구단 인수 등 복잡한 시스템은 후속 단계로 미룬다.

## 16. 핵심 데이터 모델 초안

다음 모델을 TypeScript 타입으로 구현한다. 세부 필드는 개발 과정에서 확장할 수 있다.

- `Club`: id, name, leagueId, stadium, reputation, finances, crestAssetId
- `Player`: id, name, nationality, birthDate, positions, attributes, potential, clubId, contract, photoAssetId, source
- `PlayerSeasonStats`: playerId, seasonId, appearances, starts, minutes, goals, assists, averageRating
- `PlayerCareerStats`: playerId, appearances, goals, assists, honours
- `Manager`: id, name, nationality, reputation, careerHistory
- `Competition`: id, name, formatConfig
- `Season`: id, competitionId, startDate, endDate, status
- `Fixture`: id, seasonId, round, date, homeClubId, awayClubId, status, result
- `MatchEvent`: id, matchId, minute, type, clubId, playerId, relatedPlayerId, metadata
- `Tactic`: formation, mentality, pressing, defensiveLine, tempo, passing, attackFocus
- `Injury`: id, playerId, type, startDate, expectedReturnDate
- `Transfer`: id, playerId, fromClubId, toClubId, fee, date, status
- `SaveGame`: id, schemaVersion, createdAt, updatedAt, gameDate, managerId, selectedClubId, worldState
- `AssetMetadata`: id, path, type, source, license, permissionStatus, attribution

실제 외부 데이터와 게임 내 변경 데이터를 구분하기 위해 `sourceType`, `sourceUpdatedAt`, `gameOverride` 등 메타데이터를 둔다.

## 17. 테스트 및 품질 기준

### 필수 테스트

- 구단 선택 후 새 세이브 생성
- 날짜 하루 진행 시 이벤트 중복 실행 없음
- 경기 일정 날짜에 경기 실행
- 경기 중 교체 및 전술 변경 반영
- 득점 발생 시 선수·팀·리그 기록 일관성
- 무승부·승리·패배 승점 계산
- 세이브 저장 후 새로고침 및 재접속 복구
- 잘못된 CSV 가져오기 오류 표시
- 사진이 없거나 로드 실패해도 레이아웃 유지
- 좁은 화면에서 주요 메뉴 접근 가능

- 브라우저에서 로컬 실행 가능
- 새 게임부터 첫 경기 종료까지 플레이 가능
- 핵심 버튼과 메뉴가 실제 동작
- 저장/불러오기 검증 완료
- TypeScript 오류 및 주요 콘솔 오류 없음
- 테스트 데이터와 실제 출처 데이터가 구분됨

## 19. 최종 제품 정의

완성된 게임은 사용자가 실제 K리그 구단을 선택하고, 감독으로 부임해 날짜를 진행하며, 경기마다 직접 전술과 교체를 지휘하고, 이적과 육성을 통해 구단을 장기적으로 성장시키는 싱글 플레이 축구 경영 시뮬레이션이다.

첨부된 레퍼런스의 선수 커리어 카드 감성을 유지하되, 선수 기록과 구단 역사, 리그 운영, 경기 시뮬레이션이 서로 연결되는 독창적인 웹게임을 구현한다.
